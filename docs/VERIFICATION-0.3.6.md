# 0.3.6 options, sharing and saving

Options remains open when toggling editor preview, auto-save or upload confirmation. On/Off labels now accompany switch tracks and knobs. Clicking outside or pressing Escape dismisses the menu; Settings and other commands leave it normally. The frosted workspace and opaque menu surfaces remain unchanged.

With confirmation enabled, uploading requires an explicit **Upload publicly** action beside **Cancel**, with the host and public-link visibility stated. Ordinary repeated Upload clicks cannot accept the prompt. Cancellation or changed image pixels cannot inherit approval. SHA-256 fingerprints cover the flattened image, dimensions and destination. A bounded in-memory cache stores eight recent successful links without keeping extra screenshot buffers. Repeated clicks while a request is pending start no additional request. Reusing a link performs no HTTP upload. Upload failures remain retryable and successful uploads remain cached even if clipboard copying fails. The existing ring dependency used by HTTPS also supplies hashing; no new registry packages are needed.

Auto-save defaults to **Pictures > Snipping Tool UL**, with an explicit changeable destination in General settings. Custom absolute paths are honored even when the folder has not been created. Disk failures report errors rather than silently substituting another destination. Atomic create-new filenames preserve captures with identical timestamps. Auto-save stores the original capture; manual Save stores the current annotations.

Manual Save starts a chooser worker before copying image pixels, flattening annotations or encoding an image. Once a filename is chosen, encoding and writing run on a worker. Cancelling performs no image rendering or encoding. Parallel choosers are blocked; a result for an older capture cannot save the replacement capture. Native shell initialization and actual chooser latency remain unmeasured.

Headless verification covers menu interaction, explicit confirmation and cancellation, changed-image identity, retries, stale completion events, 20,000 repeated requests before and after success, bounded link storage, configured destinations, same-timestamp collision preservation and PNG/JPEG/WebP output. Actual client renders with synthetic source pixels cover both themes, switches, the confirmation panel and General settings. These renders do not prove native titlebar appearance or end-to-end behavior.

Release installation requires fresh format, test, Clippy, mocked installer, remapped build, CLI, icon, package hash and public identity checks. The existing process is preserved and the update is not launched. No working-desktop capture, clipboard writes, visible UI, registered hotkeys, tray tests, notifications or live uploads are performed. The prior dependency audit and remaining native acceptance/publication gates are documented in [0.3.5 verification](VERIFICATION-0.3.5.md) and the [publication checklist](PUBLICATION.md).
